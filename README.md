# test-kvitto

## Настройки базы

Скопируйте `.env.example` в `.env`. Локальный `.env` исключён из Git
и контекста Docker-сборки. Значения в примере предназначены для разработки.

Обязательные переменные: `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`,
`DB_PASSWORD`. Строки не должны быть пустыми, порт — целое число от 1 до 65535.
Настройки читаются через Pydantic Settings, переменные окружения имеют
приоритет над корневым `.env`. DSN собирается для драйвера `asyncpg`.

При локальном запуске используется `localhost:5433`. В Docker Compose
приложение получает адрес `postgres:5432`, а внешний порт PostgreSQL
задаётся через `DB_PORT` в `.env`.

## Запуск

```bash
docker compose up --build
```

API: http://localhost:8002, Swagger: http://localhost:8002/docs.

Для запуска приложения вне Docker установите зависимости:

```bash
python -m pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8002
```

## Запуск тестов

Нужны Python 3.11+ и запущенный Docker. Выполняйте команды из корня
проекта в активированном виртуальном окружении:

```bash
python -m pip install -r requirements-dev.txt
docker compose -f docker-compose.test.yaml up -d --wait
python -m pytest -q
```

Запускаются пять тестов из `tests/test_acceptance.py`: суммы и промокоды,
график рассрочки, идемпотентность, переходы статусов и отсутствующий платёж.
FastAPI вызывается внутри процесса тестов; запускать Uvicorn не требуется.
Миграции применяются автоматически к отдельной базе `kvitto_test`
на `localhost:55433`. Перед каждым тестом её платежи и тарифы очищаются.
Рабочая база и файл `.env` не изменяются.

После проверки остановите тестовый PostgreSQL:

```bash
docker compose -f docker-compose.test.yaml down
```

Для другой тестовой базы можно задать переменную `TEST_DATABASE_URL`.
Используйте драйвер `postgresql+asyncpg` и имя базы с окончанием `_test`.
Дополнительные подробности — в [TESTING.md](TESTING.md).

## Миграции

Alembic использует те же настройки базы и `Base.metadata` всех моделей.
При старте FastAPI автоматически выполняется `upgrade head` до обработки
запросов. В Docker Compose приложение ждёт успешной проверки PostgreSQL.
При локальном запуске PostgreSQL должен быть уже доступен.

Первая миграция `0001` создаёт таблицы `tariffs` и `payments` и добавляет тарифы:

| ID | Название | Цена в копейках |
|---|---|---:|
| basic | Basic | 990000 |
| standard | Standard | 1990000 |
| premium | Premium | 2990000 |

Alembic сохраняет применённую ревизию в `alembic_version`. При повторном
запуске выполненные миграции пропускаются, тарифы не дублируются и их цены
не перезаписываются. Если тариф вручную удалён, перезапуск его не восстановит.
Ошибка миграции прерывает запуск API; изменения первой миграции выполняются
в одной транзакции.

Для следующих изменений моделей создавайте новую миграцию и проверяйте её:

```bash
alembic revision --autogenerate -m "describe schema change"
alembic upgrade head
```

В контейнере приложения команды выполняются через `docker compose exec app`.
Автоматический запуск миграций рассчитан на один экземпляр приложения,
как в текущем Compose. При масштабировании миграции следует запускать
отдельным шагом перед стартом экземпляров.

`app/db/session.py` содержит асинхронный движок, фабрику сессий и зависимость
`get_session`. При старте открывается подключение для применения миграций.
Транзакции подтверждаются явно в коде сервиса; при закрытии сессии
незавершённая транзакция откатывается. Движок освобождается при остановке API.
